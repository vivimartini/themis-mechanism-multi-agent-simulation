# Multi-Agent Simulation and Strategic Analysis of the Themis Mechanism

Research code accompanying the MPhil dissertation *Multi-Agent Simulation and
Strategic Analysis of the Themis Mechanism* (MLMI, University of Cambridge,
2026).

The repository implements a reference version of the Themis operating-point
calculation and evaluates strategic reporting in a calibrated nine-actor model.
The central comparison holds coverage fixed, where the price rule is
strategy-proof on the stated single-peaked domain, against endogenous coverage,
where reports also change membership and transfer rates.

## Scope

- Computational model; not a policy or welfare simulator.
- Results depend on the stated calibration, report domain, and search budget.
- The archetype reproduction uses digitised preference lines and is approximate.

### Report-domain qualification

The dissertation describes report perturbations as lying in `[-60, 60]^2`.
The CMA-ES implementation that generated the reported results instead searches
over `R^2`: [`rq2/oracle.py`](rq2/oracle.py) deliberately passes no bounds to
`cma.CMAEvolutionStrategy`. At least one reported best response (China's
coverage-coefficient perturbation, approximately `-70.1`) lies outside the
stated box. The repository preserves those submitted results rather than
silently changing the optimisation problem. They must therefore be interpreted
as results for the unbounded search used by the code, not as exhaustive evidence
over the box stated in the dissertation. A bounded-domain rerun is future work.

## Requirements

The code was validated with Python 3.13 and the exact versions in
[`requirements.txt`](requirements.txt). Create an isolated environment:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

`cma` is pinned because the stochastic optimiser's trajectory is version
sensitive. Experiments use non-zero, documented seeds; a deterministic search is
not the same thing as Monte Carlo sampling.

## Reproducing the results

From the repository root:

```bash
./run_all.sh
```

The script is the authoritative run order. It creates or refreshes derived
results in `data/`, the experiment manifest in `reference_outputs/`, and PDF/PNG
figures in `figures/`.

For a fast installation and consistency check:

```bash
git ls-files -z '*.py' | xargs -0 .venv/bin/python -m py_compile
.venv/bin/python -m rq2.validate
```

`rq2.validate` checks the reported baseline, fixed versus endogenous controls,
oracle repeatability, and agreement between the vectorised and reference solvers
under strategic reports. It is a smoke test, not a substitute for the full
pipeline, and it expects the versioned derived artifacts to be present. Run
`./run_all.sh` first if they are absent.

## Repository map

```text
engine/          Reference mechanism, scenario prior, and transfer analysis
archetypes/      Published-archetype accounting and digitised preference check
rq2/             Empirical-game experiments, robustness checks, and figures
data/            Input calibration plus experiment-generated numeric results
figures/         Experiment-generated dissertation figures
reference_outputs/
                 Generated manifest and captured run record
paths.py         Canonical paths for generated data and outputs
```

Each module that writes a result owns the corresponding `data/` file. Figure
construction reads those saved results rather than duplicating numerical
constants. [`reference_outputs/experiment_manifest.md`](reference_outputs/experiment_manifest.md),
generated by `python -m rq2.manifest`, records each experiment's question,
sampling design, seed, solver resolution, utility, and outputs.

The [`DISSERTATION_CROSSWALK.md`](DISSERTATION_CROSSWALK.md) maps dissertation
figures, tables, and headline claims to their producer modules and saved
artifacts. [`DATA_PROVENANCE.md`](DATA_PROVENANCE.md) records the status and
limitations of calibration inputs.
